## 如何解释

T384 三个输入组中，相对 interleaved，后到请求 TTFT、完成时间以及旧请求的窗口最大间隔均改善。这个受控负载说明 mixed 能够同时推进两类请求，但不意味着所有场景、所有基线下 TTFT 都改善。

相对 separate 的收益与代价见 [完整配对分析](../data/burst_requests/formal/analysis.md)；该基线下后到请求 TTFT 更长。长输入在线实验在持续到达负载下进一步观察到完成时间改善与首 token 等待增加的权衡。不能把两种负载的获益指标合并成“所有延迟均下降”。

## 记录和限制

- [全部正式测量](../../../../reports/data/burst_requests/formal)，按 block0、block3、block4 和 confirm0/1/2_T* 定位；[公开数据导出说明](../data/README.md)。
- [reuse.json](../../../../reports/data/burst_requests/formal/reuse.json) 记录从先前中断批次复用的 12 个完整调用；这些记录只计入一次。
- 所有正式调用均无抢占，但输出哈希跨策略不一致。不能声称收益已在答案等价前提下得到证明。
- 每配置三个执行重复；配对置信区间只描述重复执行波动，未经多重比较校正，不是跨任意工作负载的保证。
- 重新生成本页：`python tools/render_burst_report.py --language zh-CN`；全数据核验：`python tools/verify_results.py`。
